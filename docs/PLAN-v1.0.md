# PLAN-v1.0 · 正式可用版本路线（2026-11-14 定稿）

**使命**：从「能用的工具」到「正式可用的产品」——把 0.9.x 攒下的能力发出去、
把输出端升级到站点级、把选择面撑起来、把质量债清干净，然后以 v1.0 名号正式发布。

**北极星标尺**（[VISION.md](VISION.md)）：每个新能力都必须同时有**结构化数据形态**
（API 可驱动）与**界面形态**（人可见可改）——只有其一就是断链。

## 四、风险与既有雷区（承接 0.9.x 教训）

1. **发版链契约**：改流水线必须同步 `test_packaging_matrix.py`（字面量锁）；版本同步必须在全量回归**启动前**完成；`git push` 重试循环必须 `set -o pipefail`。
2. **每批完成必须跑 `verify_mainline.py`**——0.9.5 巡检实锤：套件绿 ≠ 服务可用（feedback resolve / recipe-run 白名单 / OKLCH 顺序三个 bug 都是它抓的）。
3. **模板接入合规**：MIT 保留版权声明入 manifest（origin+license 必填）；AGPL 系只学方法不搬码（guizang 红线）；新成员防路由平分抢占（guidance-source 不进产物候选——0.9.5 教训）。
4. **站点批不破坏单文件承诺**：单文件产物路径的行为回归门禁必须照旧全绿；站点是组装层。
5. **外部库 34 套分批接**：一次全接会让画廊 UI 变长列表——按意图分 3 小批，每批过覆盖矩阵。
