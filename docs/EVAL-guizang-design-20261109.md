| 件 | 内容 |
|---|---|
| 五个 skill | 网页 PPT / 图文卡片（小红书 3:4、公众号 21:9、1:1）/ 网页排版（忠实/解释双模式）/ **去 AI 味（humanizer-zh，MIT）** / 语气档案 |

| 去 AI 味 | 删空话/重复/模板化表达，**保留事实、确定程度与作者语气** |
| 六条工作流 | 一文三出口（网页→卡片）/ 先去 AI 味再排版 / 演讲回收（PPT+讲稿→文章）/ 品牌套件（品牌色→统一主题）/ 封面矩阵 / 中英双版本 |

## 二、与现有家底逐项比对（吸收点，不是搬运点）

| 上游能力 | 我们现状 | 差距与吸收方式 |
|---|---|---|
| 十主题设计系统（三形态一家） | 11 家 preset + 画廊 10 张，**但 preset 与模板无「家族」语义** | ✅ 高价值：给 preset/模板打 `family` 标签（guizang 系/fox 系/vercel 系…），家族内共享辅助 token——「同一篇内容做成三种出口，主题是一家人」正是拼装层的前提 |
| OKLCH 品牌色约束 | `primary` 直接覆盖（仅校验 #RRGGBB 格式），**无明度/彩度/对比度约束** | ✅ 高价值且确定性可门禁：`color-mix in oklch` 约束进风格范围 + 现有 WCAG 对比度门禁扩展 APCA——「不直接用原色」写进生成端 |
| WCAG + APCA 对比度 | 只有 WCAG | 补 APCA 有争议（未成 W3C 标准）——列为可选实验，默认 WCAG 4.5:1 不变 |
| 字体子集化内置 | 字体系统已定，**无子集化**（离线字体文件全量） | 中价值：导出/交付包时按实际用字子集化（本地 fonttools，`[font]` extra）——产物体积下降明显 |
| 语气档案（≥2 证据/条） | Project Memory 有 tone 一句话字段 | ✅ 高价值：memory.tone 升级为结构化语气档案（常用词/禁词/句长/开头结尾），**复用 0.9.2 copy_expert 的 forbidden 门禁**——润色与去 AI 味共用档案 |
| 去 AI 味 | 无 | ✅ 差异化功能（humanizer-zh 是 MIT，规则可参考实现；AGPL 部分只学思路不抄码）：「删空话/保留事实与作者语气」与 copy_expert 门禁天然互补——**切 0.9.3 与拆分语义增强同批** |
| 作品库 + 做同款 + 做新一期 | 画布工作区 + 画廊收藏 + 项目副本 | 拼装层（0.9.4）设计输入：「从任意产物做同款」= gallery item 生成通道已有；「做新一期」=连载语义（v1.0 前实验） |
| 六条工作流 | 画布推进是线性配方 | 「一文三出口」「演讲回收」正是**拼装层第一批**的现成剧本——0.9.4 工作流预设直接参考这六条 |
| 三形态（PPT/卡片/网页） | 六意图网页 + deck→PPTX 导出；**无社交卡片意图** | 供给侧不新增意图（遵守「单文件承诺」边界），但**导出端**：landing/poster 已有长图——「封面矩阵」式多尺寸出图可作导出选项（0.9.x 观察） |

  代码/文案/主题 CSS**；要复用只有两条路——(a) 联盟接入运行其插件（用户自装，
  我们只做路由，不改发），(b) humanizer-zh（MIT）可参考实现。
