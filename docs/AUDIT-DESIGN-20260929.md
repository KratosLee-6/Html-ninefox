本轮已修掉全部 P0 与两个 P1；**字号阶梯、双 token 命名空间和 P2 三项仍未开工**，见文末「待办」。

## 修复前的实测数据

### P0-1 · 节点头部挤压

`.node-head` 是 `flex-wrap:nowrap` 且标题没有收缩下限。中文模板名几乎必然触发：

```text
节点宽度 137px
├ 图标      12 × 12
├ 标题      90 × 27   ← 折成两行
└ 「风格」  12 × 21   ← 被压成竖排单字
```

现在标题先 `text-overflow:ellipsis` 截断，徽标 `flex:0 0 auto`，实测 21×16 单行。

### P0-2 · 窄屏进度条失效

`@media (max-width:760px)` 把 `.tl-title / .tl-label / .tl-status` 全部 `display:none`，390px 下整条进度只剩三个 √ 和连接线，占着约 50px 却传达不了任何信息。改为只隐藏已完成与未开始的步骤，**当前**与**失败**步骤的文字始终可见。

### P1 · 弱化文字对比度

版本号、栏目标题、模板英文描述、数量角标、状态字形共用一个 `--text-tertiary`：

| 主题 | 修复前 | 修复后 |
|---|---|---|
| 纸白 `--text-tertiary: #7A8A91` | 3.17–3.51:1 | `#59676D` 全部达标 |
| 夜蓝 `--text-tertiary: #829BA5` | 3.98–4.57:1 | `#A0B6BE` 全部达标 |

问题被字号放大：这些文字只有 9–11px，而 WCAG 对小字本就要求 4.5:1（大字号才降到 3:1），属于双重不达标。

### P1 · 夜蓝主题主按钮（修复过程中新发现）

`.btn-primary` 等五处把 `color:#fff` 写死在 accent 底上。夜蓝 `--accent` 是亮蓝 `#76A5FF`，白字压上去只有 **2.44:1**——受影响的是「推进当前工作区」这个全站最重的 CTA。

新增语义令牌 `--on-accent`（纸白 `#FFFFFF` / 夜蓝 `#0C1B2E`），五处统一改用它，品牌配色不变。

## 待办（下一批）

### 1. 双 token 命名空间与硬编码 px

两套 token 文件命名同义但互不引用，换肤要改两处：

| 系统 A（`workbench-system.css` + `index.html`） | 系统 B（`pixel-garden-tokens.css`） | 引用量 |
|---|---|---|
| `--bg-base` | `--brand-bg` | 18 / 3 |
| `--text-primary` | `--brand-text` | 36 / 3 |
| `--font-display` | `--font-serif` | 1 / 1 |

同时有 40 处硬编码 px 绕过 token，其中大量不在网格上（7 / 9 / 10 / 11 / 13 / 15 / 17 / 19 / 22），而 `--space-*` 只定义了 4 / 8 / 12 / 16 / 24。**间距系统事实上不存在。**

> 字号部分已先行收敛：142 处 `font-size` 字面量全部改为 `var(--fs-*)`，静态取值由 17 种降为 7 档（`--fs-2xs:9 / xs:10 / sm:11 / md:12 / lg:14 / xl:19 / dsp:30`），运行时主工作台去重字号为 6 种。**间距与 token 命名空间合并仍待做。**

### 3. 文字色层级与字重（字重已收敛，色层级的天花板已算清）

**字重已收敛**：35 处 `font-weight` 字面量全部改为 `var(--fw-*)`，四档 `--fw-normal:400 / medium:500 / semibold:600 / bold:700`；非标称的 560 / 650 / 800 全部并入。`classic.html` 是独立页面（自带 `:root`、不加载系统 CSS），已同步补上同一套四档。

**文字色层级的天花板已算清**：纸白主题下 `--text-secondary` 5.98:1、`--text-tertiary` 5.76:1，只差 0.23，实际不可区分；而在 `--bg-hover`（纸白主题最深的底色）上，能过 AA 的最浅 tertiary 恰好就是现在这个值（L ≤ 0.1428），**一点余量都没有**。结论是这个主题客观上撑不起三级文字色，层级应由**字号（7 档）+ 字重（4 档）**承担，颜色只保留两级语义 + 一个 muted。不要为了"拉开层级"把 tertiary 调浅——那会直接打破 AA。

### 4. P2 精修三项（已修）

- **首屏画布把内容缩到 0.33 倍、右侧空出 666px**。根因不是留白太大，而是 `canvasFitInsets()` 把左上角那块浮层「工作区导航卡」当成**通高左栏**避让（`left: 导航卡右缘` = 290px），916px 画布只剩 446px 可用。现在按各浮层真实几何分别计入上/下/右三边，fit 留白 90→36px，小地图 196×130→150×100。**首屏缩放 0.33 → 0.80**，内容利用率 39% → 42% 且居中。
- **侧栏模板卡 179px、标题断词换行**。`.pal-name` 是 flex 容器，模板名与英文描述是兄弟节点，描述一换行就把标题挤成断词换行并撑高卡片。改为上下堆叠、各自夹 2 行，实测标题 3 行 → 2 行、卡片 ≤170px；`REAL HTML` 徽标从缩略图左上（压内容）移到左下。
- **弹窗**：吸收指标从一行调试串改为指标条（数字为主、状态色条区分待审/已采纳/已拒绝）并补回区块标题；四个筛选按钮按当前状态切换主/次样式并带 `aria-pressed`；背景模糊 12px → 6px。

> 修正记录：本节初版称「弹窗高 900px 但内容只有 336px、大片空置」——**该判断是错的**，900px 是全屏遮罩本身，弹窗按内容自适应。此条已撤回。

回归门禁 `tests/test_layout_hierarchy_gates.py`（8 条）覆盖：画布避让模型、首屏缩放、画布宽度利用率、模板卡高度与夹行、指标条层级、筛选选中态、批量导入可达性、背景模糊。

## 方法论：三条探针规则

`scripts/design_audit.py` 已把这三条编码进脚本，改动前请先读：

1. **半透明自身底色**。`.template-badge` 是白字压在 `rgba(17,28,42,.82)` 上。若像普通元素那样向上穿透找不透明祖先，会得到「对比度 1:1」的假警报。规则：元素自身背景 alpha > 0.5 时用自己的底色。
2. **画布缩放**。`.node-head` / `.ws-head` 内控件随 `camera.z` 缩放，非 100% 缩放下量 `getBoundingClientRect` 测的是缩放而非控件。规则：触控目标一律在 `camera.z = 1` 下量。
3. **主题值**。夜蓝是 `data-theme="pixel-night"`，不是 `"night"`。写错不报错，只会静默量到纸白数据——第一版因此把两个主题测成了同一组数字。

## 被推翻的初始印象

设计体检最容易把「看着别扭」当成缺陷。以下三条最初怀疑、实测后证伪，**不列入问题清单**：

| 初始怀疑 | 实测结论 |
|---|---|
| 弹窗内输入框 / 下拉 / 按钮高度不齐 | 三者**全部 36px**，基线良好，是视错觉 |
| 「REAL HTML」徽标对比度 1:1 | 实为白字深底，高对比；探针跳过 0.82 透明度底色导致误判 |
| 顶栏存在无可读名称的按钮 | 10 个控件**全部带 aria-label 且 ≥36px** |

另：报告初版曾称「适配 / 推进 54×21 触控目标过小」，该数字受画布缩放影响；真实缺陷只是 CSS 里写死的 `height:22px`，已修至 28px（触屏 44px）。
