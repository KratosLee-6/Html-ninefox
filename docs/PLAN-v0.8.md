## 1. 迭代切分

### v0.8.0 · DOCX 导出（补交付矩阵）+ paraphrased 重改（收吸收链路）

**Word 导出（docx 语义版）**：导出中心 v0.4 设计文档的原文承诺——「把
标题、段落、列表、表格、图片、引用和分页映射为 Word 文档结构」。PPTX
半边 v0.6 已落地，这是剩余的最后一格。

- `htmlninefox/docx_export.py`，照 PPTX 全部惯例：`python-docx` 进可选
  extra `[docx]`（未装如实提示，离线承诺不破）；**降级清单如实上市**
  （复杂 CSS 布局不映射、逐项列出被丢弃内容，不承诺无损）；
- 语义映射第一版（宁小勿假）：h1–h6 → Heading 1–6、段落、ul/ol、table、
  img（data: URI 内嵌）、blockquote、hr；
- 按意图分工：doc / archdoc → 全文语义版；deck → 讲义式大纲；landing /
  poster / dashboard → 引导走高保真 PDF（说明 DOCX 不是正确形态）；
- 门禁：python-docx 回读逐项断言结构；降级清单完整性（声称丢弃的产物里
  真没有、声称保留的真在）；未装 extra 全套件不 skip；变异全 CAUGHT。

**paraphrased「重新改写」**（v0.7.7 遗留，小）：`/api/intake/page-blocks`
增 `retry_paraphrase` 参数（跳过 LLM 缓存重算）；审核台对 paraphrased 块
加重改按钮。真链扩一条 + 变异。

> 为什么导出先行：它建立 `[docx]` extra 与 docx 解析工具层，是 v0.8.1
> 导入的地基。两个方向共享同一套解析底座，顺序做不浪费。

### v0.8.1 · DOCX 导入 + AI 理解补全（本版主打）⭐

**用户场景**：手里只有一份 Word 文档——文字和结构在，但没有任何图片、
背景色、风格。现在的产品没法从这里出发。目标：**贴入 DOCX，AI 理解内容，
自动补齐视觉层提案，人只需审核微调**——把「人为操作的步骤」压到最少，
同时每一步 AI 的判断都可见可改（VISION 交接产物原则）。

**管线设计**（五步，每步的交接产物都有机器+人双形态）：

1. **上传解析**（离线，无 LLM 也能走完）：审核台新增 .docx 上传（与 ZIP
   并列；docx 本质是 OOXML zip）。解析出 `docx_outline` 交接产物：标题
   层级（Heading 1–6 → 块层级）、段落、列表、表格、**内嵌图片提取**
   （word/media/* 成为资产候选——文档里其实有图的，不该丢）、文档元属性。
2. **AI 理解提案**（配置了 LLM 时，`[llm]` 既有通道）：对大纲做一次
   结构化提案，产出 `docx_proposal` 交接产物：
   - **意图判定**：内容最适合六类中的哪类（报告/文档 → doc / archdoc；
     章节化演讲结构 → deck），附判定理由；
   - **风格提案**：按领域与语气提出设计令牌（主色/字体/圆角，从内置
     预设选或给覆盖值），附理由——「为什么是这个配色」要能被人读懂；
   - **图片计划**：识别缺图位置（封面/章节分隔/要点配图），产出
     `ImagePlanItem[]`：`{slot, 用途说明, 图像提示词}`。**v0.8.1 承诺的
     是提案与占位**——提示词可直接拿去任何图像模型生成后回填；图像模型
     的自动接入（MiniMax 等Provider 选型与成本）是独立决策点，不是本项
     前提（原则 2：LLM/图像模型都是升级不是依赖）；
   - **文案提炼**：headline / 摘要 / 小节精炼（长段落压成可读的产物文案，
     原文进 provenance 管道按许可处理——本地产文档默认 verbatim 可用）。
3. **人审提案**：`docx_proposal` 落进审核台——意图可换、风格可改、图片
   位可增删、文案可编辑。**AI 给建议，人拍板**，这一步没有黑盒。
4. **采纳生成**：采纳后大纲映射为 blocks 走既有分块通道（六生成器全接入，
   无需新渲染路径）；风格令牌走既有 preset 面板。**不新造管线，串联既有件**。
5. **离线兜底**：未配置 LLM 时，规则引擎给默认提案（intent=doc、默认
   预设、无图片计划只留占位位），人可全手调——功能不缺失，只降级，
   且降级方式如实标注。

**门禁**：真链验收（真实 docx → 解析 → 提案 → 采纳 → 六类产物逐类断言
标题层级/表格/图片到达）；无 LLM 兜底行为锁定（与 v0.7.7 离线形态同一
纪律）；提案产物的机器形态 schema 锁定（外部 agent 可驱动）；变异全 CAUGHT。

### v0.8.2 · 键盘可达性 + Tauri 决策

- **键盘可达性专项**：C6 迁移后残留的 `<div onclick>`（classic 历史项、
  预览页等）补 role/tabindex 或语义化为 button；Tab 序走查门禁（全部
  data-action 控件键盘可达）。范围限定「键盘可操作」，读屏器审计另立。
- **Tauri 桌面壳**：两个决策点未定案不动工——①与刚验证过的 PyInstaller
  矩阵**并存还是替换**（建议并存：壳=窗口+webview+sidecar+托盘，PyInstaller
  继续作无 Rust 环境兜底）；②Rust 工具链进 CI 的成本。壳的验收沿用
  verify_portable 纪律：启动后必须真探测到后端健康端点。

### 明确不做（v0.8）

- **图像模型的自动接入**：作为 v0.8.1 图片计划的后续配置项独立决策
  （Provider 选型/成本/密钥管理），不阻塞提案与占位交付；
- **云同步 / iOS Companion**：服务端架构与账号体系决策是 v0.9+ 立项问题；
- **插件市场 / 生态**：需求信号不足，维持观察；原生移动包维持缓发。

## 2. 惯例承诺（每个迭代都适用）

- 每个功能配真链验收 + 变异门禁；删除修复必须变红；
- 「离线可用」不被任何新能力绑架——可选依赖只做增强，降级如实标注；
- 新功能立项必须过 VISION 三问：交接产物是什么、人在哪里看、在哪里改；
- 数字（测试数、资产数、变异捕获数）全部实测进文档，绝不手写。

## 3. 当前状态与推进方式

- 本文档是规划，不携带实现；v0.7.8 后主干零欠账。
- v0.8.0 边界清晰，说开始就开始；v0.8.1 是用户点名的关键项，设计已
  到管线级，动工前需确认一处：图片计划的第一版是否要接某家图像模型
  直出（默认不接，占位+提示词先行）；v0.8.2 的 Tauri 部分等决策点答复。
