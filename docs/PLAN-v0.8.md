## 1. v0.8 主题与迭代切分

### v0.8.0 · DOCX 语义导出 + 吸收链路收尾

**主线：Word 导出（docx 语义版）**——导出中心文档的第 35 行早在 v0.4 就
写明了设计：「把标题、段落、列表、表格、图片、引用和分页映射为 Word 文档
结构」。这是导出矩阵自己预告的最后一格，也是文档型产物（doc / archdoc）
交付闭环的刚需。

- 新增 `htmlninefox/docx_export.py`，照 PPTX 的全部惯例：
  - `python-docx` 进可选 extra `[docx]`（未安装如实提示，离线可用承诺不破）；
  - **降级清单如实上市**——复杂 CSS 布局不映射、逐项列出被丢弃的内容，
    不承诺「任意 HTML 无损转 Word」（导出中心原则第 16 行原文）；
- 语义映射范围（第一版，宁小勿假）：h1–h6 → Heading 1–6、段落、ul/ol、
  table、img（data: URI 内嵌）、blockquote、hr；
- 按意图分工：doc / archdoc → 全文语义版；deck → 讲义式大纲；landing /
  poster / dashboard → 引导走高保真 PDF（说明为什么 DOCX 不是正确形态）；
- 导出中心加 Word 选项 + 兼容性评分报告覆盖 docx。

**副线：paraphrased「重新改写」**（v0.7.7 遗留，小）：
- `/api/intake/page-blocks` 增 `retry_paraphrase` 参数（跳过 LLM 缓存重算）；
- 审核台预览块上对 paraphrased 块加重改按钮——预览即所得模型下的显式重试；
- 门禁：真链扩一条（重改后文本变化且仍过忠实度门禁）+ 变异。

**验收判据**（照仓库惯例，不是「做完了」而是「能证明」）：
1. 真实产物 → docx 字节校验：python-docx 回读，断言标题层级/表格/图片
   逐项到达；
2. 降级清单完整性门禁：清单里声称丢弃的，产物里必须真没有；声称保留的
   必须真在（防「降级清单」变成免责装饰）；
3. 未装 `[docx]` extra 时：导出中心选项可见但如实提示，全套件不 skip；
4. 变异脚本全 CAUGHT；全量回归数字如实进发布说明。

### v0.8.1 · 键盘可达性专项

C6 迁移后残留的最后一个交互债：`<div onclick>`（classic 的历史项、
workbench-features 的预览页等）对键盘用户不可达。

- 非 button 宿主补 `role` + `tabindex` 或语义化为 `<button>`；
- Tab 序走查：全部 data-action 控件键盘可达（Playwright 键盘走查门禁）；
- Escape / 焦点环与 interaction-system 既有对话框管理层对齐；
- **范围界定**：本版只做「键盘可操作」，不含读屏器全面审计（另立专项）。

### v0.8.2 · Tauri 桌面壳（动工前需拍板，见决策点）

**两个决策点，未定案不动工**：

1. **并存还是替换？** 建议并存：Tauri 壳（窗口 + webview 指向
   127.0.0.1:8620 + sidecar 拉起 python 后端 + 托盘）只是**交付形态**，
   PyInstaller 矩阵（v0.7.6 建成、真启动验证 + 字节回读）继续作为无
   Rust 工具链环境的兜底。替换等于推翻一套刚验证过的交付链。
2. **Rust 工具链进 CI 的维护成本**是否值得：Tauri job 需要 Rust + 双平台
   webview 依赖，构建时长与失败面都会涨。

**范围草案**（定案后细化）：壳自身不含业务逻辑；产物验证沿用
`verify_portable` / `verify_unix_portable` 纪律——壳启动后必须真的探测到
后端健康端点才算构建成功。

### 明确不做（v0.8）

- **云同步 / iOS Companion**：需要服务端架构与账号体系决策（数据放哪、
  加密边界、同步冲突语义），是 v0.9+ 的立项问题，不是 v0.8 的功能项；
- **生态 / 插件市场**：需求信号不足，维持观察；
- 原生移动包：维持缓发决策不变。

## 2. 惯例承诺（每个迭代都适用）

- 每个功能配真链验收 + 变异门禁；删除修复必须变红；
- 「离线可用」不被任何新能力绑架——可选依赖只做增强；
- 数字（测试数、资产数、变异捕获数）全部实测进文档，绝不手写；
- HTTP 接口变化如实写进发布说明「性质」栏。

## 3. 当前状态与推进方式

- 本文档只是规划，不携带任何实现；v0.7.8 之后主干保持零欠账状态。
- v0.8.0 的两项（DOCX、重改）边界清晰、无需拍板，说开始就开始；
  v0.8.2 的两个决策点需要明确答复后再动。
