# v0.6 迭代规划：设计吸收流水线（Design Intake Pipeline）

- 制定日期：2026-09-26
- 起点：`v0.5.0` 稳定版（2026-09-25 发布，含 macOS 包）
- 主题：**让模板、风格、内容、组件、装饰、动效六个层面，能够最快速度吸收全世界的优秀设计**
- GitHub 总追踪：建议开 Issue #7（v0.6 delivery map）
- 预计投入：20～28 个有效工作日，约 5～7 周

## 一、定位

v0.5 完成了"创作工作台"的骨架与稳定性；v0.6 解决的是**供给**问题——工作台里的模板、风格、组件、装饰和动效，不再只靠官方手工出品，而是建立一条持续吸收全球优秀设计的流水线，让九尾狐成为一个"越用素材越厚"的创作台。

三条吸收通道，全部汇入统一的**素材审核台**，再分发到六个资产层：

```text
通道 A · 手动导入（增强现有）      通道 B · 预设源抓取（新增）      通道 C · AI 辅助分析（新增）
  单 HTML / 文件夹 / ZIP / URL      内置设计源清单 + 适配器          URL / 截图 → LLM 设计分析
  （现有私人模板库增强）            （计划性更新，随版本内置）        （OpenAI-compatible 接口）
            ↓                              ↓                              ↓
                      ┌─────────── 素材审核台（新 UI）───────────┐
                      │  来源 · 许可档位 · 去重 · 人工确认入库      │
                      └──────────────────┬───────────────────────┘
                                         ↓
   六个资产层：模板（gallery）· 风格（tokens 预设）· 组件（BLOCKS/LAYOUTS）
             · 装饰（纹理/图形/图标）· 动效（motion 样式）· 内容（文案配方）
```

## 二、与现有系统的衔接（全部长在已有架构上）

| 资产层 | 现有基础 | v0.6 增量 |
|---|---|---|
| 模板 | 私人模板库（单 HTML / 文件夹导入、页面识别、page role）、6 套原创 gallery | 批量导入 ZIP / URL；自动意图分类与质量评分；模板"基因卡"（来源+许可+令牌摘要） |
| 风格 | `_tokens.py` 11 套视觉系统 + 设计令牌提取 | 从参考页提取 palette / 字体 / 间距 / 圆角 → 风格预设候选；风格聚类去重 |
| 组件 | BLOCKS / LAYOUTS 常量 + gallery 页面抽取 | 区块级（section）抽取：导航、hero、定价表、FAQ 等 → 组件候选库 |
| 装饰 | 模板内联纹理与像素图形 | 装饰元素库（仅收录可再分发的开放许可素材；商用素材只登记"去哪里买"） |
| 动效 | motion-system 三档偏好 + motion-lab 六类样例 | 从参考站提取动效模式（时长/缓动/触发），生成符合动效预算与减少动效偏好的样式候选 |
| 内容 | brief 专家 + Recipe Run | 文案配方（标题/栏目结构）随模板入库，按意图检索 |

现有 `AllianceRouter` 继续负责"技能"层（外部 skill 调用），与素材层分工不变。

## 三、通道 B 细则：预设源抓取

**"提前写进程序"的形态**：`htmlninefox/data/sources/*.yaml` 源清单随版本发布，每源一个适配器：

```yaml
id: land-book
kind: gallery            # gallery | components | motion | typography
license_class: reference # open | reference | inspiration-only
entry_url: https://...
rate_limit: { requests_per_minute: 10, respect_robots: true }
extract: { page_skeleton: true, tokens: true, screenshot: true }
```

- 抓取产物是**参考证据**（骨架 / 令牌 / 截图），不是直接拷贝的 HTML；入库素材由九尾狐生成管线重新渲染为原创产物。
- **许可三档**（延续 DESIGN-SOURCES.md 的审计纪律）：
  - `open`：MIT / CC0 等可再分发 → 可整条入库
  - `reference`：可参考结构风格重写 → 只提取令牌与骨架，产出原创
  - `inspiration-only`：仅截图进灵感板，不提取代码
- **安全边界（写进验收）**：仅允许 http/https；请求前解析并校验 host，拒绝环回、私有与保留地址（防 SSRF / DNS rebinding）；每源独立超时与体积上限；robots.txt 遵守；抓取行为手动触发，无后台爬虫。
- 更新方式：源清单随版本更新（写进程序）+ 用户可放置自定义 `~/.htmlninefox/sources/` 扩展（手动更新通道）。

## 四、通道 C 细则：AI 辅助

- 输入：URL（走同一抓取管线取证）或用户上传截图。
- LLM 任务：布局系统分析、风格基因描述、组件清单、意图分类、命名与打标、跨素材去重聚类。
- 输出：结构化 design brief → 进审核台；确认后由现有生成管线渲染为原创候选。
- 复用现有 AI 设置（OpenAI-compatible + 本地 Key），无 Key 时通道 C 整体不可用但不影响 A/B。

## 五、辅线

1. **可编辑 PPTX / DOCX 导出**（v0.4.1 起的既有承诺）：排在流水线 Phase 2 之后；先受控可编辑 PPTX（结构 + 文本 + 占位图），DOCX 跟进。
2. **Tauri 桌面壳**：移至 v0.7——v0.6 主线是素材供给，桌面壳不阻塞任何用户价值。
3. **移动端决策记录（2026-09-26，用户确认）**：原生安卓 / iOS 包**缓发，等真实需求出现再推进**；移动端以 PWA（局域网 + 添加到主屏幕）为准。针对"HTML 文件在手机上没法完整快速查看"的痛点，v0.6 轻量解法：导出中心的**长图 / PDF 分享**（已具备）作为移动端查看形态 + 局域网二维码文档化。capabilities 中 `ios: planned / android: later` 维持不变。

## 六、阶段划分

| 阶段 | 窗口 | 交付 |
|---|---|---|
| Phase 1 · 流水线骨架 | 2026-09-28 ～ 10-11（2 周） | 源清单格式 + 抓取框架（含 SSRF 防护与许可三档）+ 审核台 UI + 手动导入增强（ZIP/URL 批量） |
| Phase 2 · 吸收上量 | 2026-10-12 ～ 10-25（2 周） | 内置首批 8～12 个设计源适配器；令牌→风格预设、区块→组件库；动效模式提取；AI 分析通道 |
| Phase 3 · 可编辑导出 | 2026-10-26 ～ 11-06（2 周） | 受控可编辑 PPTX；DOCX 视进度顺延 v0.6.x |

每阶段沿用 v0.5 的闭环：实现 → 回归 → 浏览器验收 → 文档 → 推送 → CI 绿 → 关 Issue。

## 七、验收标准（v0.6.0 退出条件）

- 从任一内置源完成一次完整吸收：抓取 → 审核台确认 → 模板 / 风格 / 组件至少各入库 1 条 → 工作台可选用并生成原创产物。
- 每条入库素材可追溯：来源 URL、许可档位、抓取时间、提取摘要。
- 抓取框架通过 SSRF 用例（私网 / 环回 / 重绑定拒绝）与限速用例。
- 可编辑 PPTX 在 PowerPoint / WPS 中打开且文本可编辑。
- 既有门禁不退化：全量 pytest、Chromium e2e 双引擎、DSH、打包矩阵（Windows / Linux / macOS / wheel / Docker）。
- 移动端能力不回退：390px 任务视图、PWA 安装、导出长图分享。

## 八、风险

- **版权**：最大风险。以许可三档 + 只提取不拷贝 + 原创重渲染兜底；任何模糊来源走 `inspiration-only`。
- **抓取目标改版**：适配器按源隔离，单个源失效不影响其他；源清单可热更新（用户目录覆盖）。
- **素材质量噪声**：审核台人工把关 + 使用次数信号（复用现有 adoption 机制）自然淘汰。
- **范围蔓延**：Tauri、云端化明确出列至 v0.7；审核台只做最小闭环（列表 + 确认/拒绝 + 元数据）。
