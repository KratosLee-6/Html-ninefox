## 一、PDF 反向拆解（主项）

`htmlninefox/pdf_import.py`：`pdfminer.six`（纯 Python）进可选 extra
`[pdf]`——未装如实提示 `pip install 'htmlninefox[pdf]'`，离线承诺不破
（可选依赖纪律与 `[docx]`/`[pptx]` 同款）。

- **只信文本层**：提取页码、字块、字符区间；标题层级靠字号与坐标推断
  （宁小勿假，推断出的层级如实标注）；
- **扫描件如实报**：无文本层的页写进 limitations「第 N 页无文本层，未提取
  文字」，不硬拆、不 OCR 兜底（OCR 属 provider 决策，见下）；
- **evidence＝页码＋字符区间**：`page` 与 `chars` 都是契约 locator 键，
  抽样回读比对进合同门禁（与 pptx 同一条纪律）；
- **边界常驻**：表格靠坐标猜、版面硬还原能得到「看着像、结构错」的结果
  ——产出「结构对、样式朴素」，两者写进 limitations；
- **门禁**：解析合同（真实 PDF fixture，含扫描页反例）＋ API 镜像
  `/api/intake/pdf(+/adopt)` ＋ 六意图真链 ＋ 变异 `mutate_pdf_gates`
  并入 preflight（第七套）；
- **估时**：1–1.5 天（扫描件与坐标噪声是主要工作量，DESIGN §6）。

## 二、图片资产环节（次项）

- **上传即资产候选**：尺寸与格式用 stdlib 解析 PNG/JPEG 头（零新依赖）；
  主色提取需要 Pillow——进可选 extra `[image]`，未装降级为「只有尺寸」
  并如实标注。**这是仓库第一个新的可选 extra，立项默认接受，发布前可否决**；
- **与图片计划打通**：v0.8.1 的图片计划（slot＋提示词＋占位）在审核台
  可挂真实资产；文字转写（OCR/视觉模型）保持 provider 决策，默认关、
  界面写清「未配置」，不自动装任何东西；
- **明确不做**（DESIGN §7）：图片直接拆成页面——图片没有结构，只能当资产。
