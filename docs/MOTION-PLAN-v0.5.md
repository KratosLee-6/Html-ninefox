# 九尾狐动效迭代方案 · v0.5

日期：2026-09-18。范围：Html九尾狐 Web / PWA 工作台及未来桌面壳。

状态：第一轮原生动效基础与交互样页已完成，详见 [交付及测试记录](ITERATION-MOTION-20260918.md)。第三方候选库尚未安装；先前浏览器联网核验受审批服务错误影响，资源当前版本、源码与许可证仍待核实。下文保留分阶段目标。

## 1. 设计目标与已有基础

沿用已定稿的 Pixel Garden：暖纸白、钴蓝、薄荷绿、少量像素识别。运动表达“连接、编排、生长、交付”，不更换现有品牌。常规反馈沿用 VI 中的 100–180ms，面板切换 180–240ms，拖动与手动平移保持跟手。

当前 `index.html` 已有：

- 程序化相机定位缓动，手动拖动使用 requestAnimationFrame。
- 节点入场 / 落位与 SVG 连线增量渲染、出现 / 删除动画。
- 与真实任务进度关联的进度环、生成扫描、成功和失败状态。
- Toast 与手机抽屉过渡。
- 部分 `prefers-reduced-motion` 适配。

当前缺口：

1. 时长与缓动分散，缺少统一的开关、取消、替换和清理机制。
2. 减少动态效果尚未全面覆盖按钮旋转、文字闪烁、Toast、抽屉等路径。
3. 动画清理需要覆盖禁用动画、节点移除和快速重试。当前 `animateNode` 依赖 animationend，失败进度环延迟清理也需要隔离后续新任务。
4. 生成过程连续轮询触发 Toast，适合改为固定的阶段状态更新，阶段变化才提示。
5. 100 节点现有测试验证脚本操作耗时；需要补真实指针操作的帧间隔和动画负载测试。

业务约束：`advanceWs` 当前通过 `members.find(n => n.kind === 'skill')` 取一个 Skill，再向后端传单个 `skill` 字段。第一轮动效表达需求、模板、风格与素材组合；展示“两个 Skill 实际协作”之前，必须先实现多 Skill 输入、执行与结果溯源。

| Motion Sites | 学习节奏、过渡、留白与信息揭示次序 | 按用户描述作为灵感站；确切网址待确认。记录参考案例的交互规律，重新实现适合工具的行为 | 设计参考 |
| Showreel Design | Logo 动态使用、版式、材质与品牌一致性 | 按用户描述作为品牌参考；确切网址待确认。沿用九尾狐既有 Logo 与 VI，仅提炼动态规律 | 设计参考 |
| React Bits | 选中反馈、有限文字强调、卡片出现 | 逐组件评估 React、动画及图形依赖；简单效果用原生实现。确有收益的组件再评估独立挂载与依赖成本 | P2：选择性采用 |

核验入口（尚未在本轮读取）：[Anime.js](https://animejs.com/)、[React Bits](https://reactbits.dev/)、[Aceternity UI](https://ui.aceternity.com/)、[Uiverse](https://uiverse.io/)。Motion Sites 与 Showreel Design 暂不猜测域名。

## 3. 第一阶段：统一基础反馈

交付：`motion-system.js`、动效令牌、标准控件状态和一页本地交互样页。

建议接口：`FoxMotion.play(name, targets, context)`、`cancel(scope)`、`setPreference('system'|'reduced'|'off')`。返回可取消句柄。这里的接口尚未实现。

- 时长建议：即时反馈 100–140ms，选中与轻强调 140–180ms，抽屉 / 弹窗 180–240ms。
- 弹窗关闭立即完成焦点处理；视觉退场不得延迟键盘操作或业务提交。
- 减少动态效果模式保留文字、图标和静态边框状态，关闭非必要位移、缩放、扫描和循环。
- 每个动画作用域记录节点 ID 与任务 ID。新任务替换旧任务时取消旧动画及其计时器。
- 相机和节点坐标仍由现有画布控制。装饰动画作用于内部视觉层，避免与定位 transform 争用。
- Toast 只提示关键阶段、成功与失败，百分比留在固定状态区域。

验收：开关切换立即生效；连续打开 / 关闭 100 次不累积监听器；关闭动效后所有功能可完成；失败后立即重试不会被旧计时器清掉进度；键盘焦点和触屏命中保持准确。

## 4. 第二阶段：生成流程的连续反馈

交付：需求 → 输入组合 → 生成阶段 → 验证 → 产物的可取消时间线。

| 真实事件 | 视觉反馈 | 时间建议与规则 |
| --- | --- | --- |
| 用户确定本次输入 | 相关卡片边框短暂强调，连接目标清晰可见 | 约 140ms，不移动真实节点 |
| 后端进入组合阶段 | 在真实输入关系上播放一次连线强调 | 单次约 180–240ms；只画本次确实采用的输入 |
| 后端进入生成 / 验证 | 稳定的阶段名称与真实进度 | 未知进度显示阶段状态，不编造百分比 |
| 产物持久化成功且预览就绪 | 输出卡片淡入，连接到位，成功标识出现 | 总序列目标 280–450ms；内容就绪即允许操作 |
| 生成失败 / 取消 | 停止连线强调与进度运动，保留可重试状态 | 约 120ms 的边框 / 图标变化，无摇晃 |
| 恢复历史版本成功 | 新版本条目短暂强调，预览更新 | 约 160ms，仅在 API 成功后触发 |

时间线绑定实际 Recipe Run 状态，不能用固定动画时长模拟后端完成。离开工作区只取消视觉播放；是否取消生成任务通过独立业务操作决定。快速任务可合并中间视觉步骤，长任务不循环播放整段揭示动画。

Anime.js 试验范围限定为“已有输入强调 → 连接强调 → 新产物出现”。比较其与原生实现的代码复杂度、取消行为、传输体积和帧耗时，再决定是否成为正式依赖。

验收：离开 / 返回、快速连点、节点删除、任务失败、重试和减少动态效果都不重复创建产物；动画结束与否不影响保存；多个工作区互不串状态。

## 5. 第三阶段：打包、性能与跨端

交付：本地依赖与来源清单、性能报告、桌面和手机验收录像 / 截图。

- 新增动效依赖压缩后传输体积目标不超过 40KB，作为准入目标，实测前不宣称达标。
- 同时播放的非必要强调初始预算为 8 个目标，离屏节点不播放；该上限经实测调整。
- 动画以 opacity / transform 为主；SVG 描边只用于少量活动连线，需单独测量绘制成本。
- 无活动任务时，不运行装饰性逐帧循环；隐藏标签页暂停视觉播放，返回时对齐最新业务状态。
- 基准桌面测量 100 节点 / 99 连线下的拖动、框选、缩放、连线和生成揭示。目标为 60Hz 屏幕下 p95 帧间隔 ≤20ms，且不引入超过 50ms 的动效长任务；当前尚未实测此指标。
- 增加带真实预览 iframe 的代表性场景，单独记录内存与帧耗时，不能用纯便笺数据代替。
- Windows Chromium / WebView2 与手机宽度先验收；macOS / iOS Safari 分别实测后再标记支持。

本地打包注意：目前 `pyproject.toml` 只显式包含 `server/static/*.js` 等平级文件。若把 Anime.js 放到 `static/vendor/`，需要同时修改包资源规则、服务端静态文件路由、Service Worker 缓存清单，并保留许可证文件。以 wheel 安装后的断网启动验收，不能只在源码目录里成功。

联网库核验完成前，第一阶段的 CSS / 原生动效治理可独立实施。正式采用第三方源码时记录准确版本、原始来源、LICENSE、NOTICE、依赖和哈希；检查是否涉及字体、图像、演示素材或付费组件的独立许可。

## 6. 首轮实施顺序

1. 建立本地动效样页，覆盖按钮、选中、连线、阶段切换、产物出现、版本恢复六类动作，提供普通 / 减少 / 关闭三种模式。
2. 优先接入统一生命周期与任务隔离，补齐减少动态效果覆盖，修复已识别的重试清理风险。
3. 以真实生成流程试验 Anime.js，与原生实现比较；完成许可和离线打包核验后才作为依赖采用。
4. 挑选少量 Uiverse / React Bits / Aceternity 候选交互，使用九尾狐令牌重新统一。
5. 通过性能与跨端门禁后进入 RC2 发布候选；多 Skill 编排另设业务能力任务。

首轮已交付统一动效基础、真实进度提示治理、重试清理修复与六类交互样页。Anime.js 时间线、真实版本恢复强调及帧性能门禁仍属后续阶段；以实际代码和测试证据验收。
