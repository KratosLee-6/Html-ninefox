# Release Notes · v0.6.0（准备发布）

> **状态：准备发布，尚未发布。目标发布日期 2026-11-08**（发布窗口 11-01 ～ 11-14，其前置 7 天稳定化窗口 M5 为 11-01 ～ 11-07）。
> 本文件随 S19 文档阶段产出，截图实拍（S20）与打 tag / 构建附件 / Release（S21）尚未执行；文中不含任何下载链接或校验和。

v0.6 是一条以「**吸收**」和「**交付**」为主线的版本。

**支柱一 · 设计吸收流水线**：工作台可以主动抓取外部设计参考，经过安全校验、候选提取与人工审核，最终落成六层可直接使用的资产——组件库、渐变装饰、动效模式、风格预设、AI 设计分析 brief 与吸收指标面板。内置 12 个设计源，覆盖 gallery / components / motion / typography 四类，每类按三档许可分级。

**支柱二 · 可编辑 PPTX**：deck 产物可以在工作台里逐页编辑文字、编辑结果回写进幻灯片结构，再导出为真正的 `.pptx` 文件，PowerPoint 里每个页面的标题与要点文本框都可继续编辑。不是"截图式"导出。

前序版本 `v0.5.0` 的用户可直接升级：Project schema、HTTP v1 与 Revision 历史完全兼容，数据目录不迁移、不覆盖旧项目。

## 新增

### 设计吸收：三条通道 → 素材审核台 → 六资产层

- **安全抓取框架**：仅允许 http/https；解析时拒绝私网 / 环回 / 保留地址；重定向逐跳过门；抓取完成后做 DNS rebinding 比对并丢弃结果；体积上限与每源限速。
- **源清单**：内置 12 个设计源（四类 kind × 三档许可），支持用户目录同 id 覆盖。
- **候选提取与素材审核台**：抓取结果落为 pending 候选（标题、意图猜测、颜色 / 字体令牌、区块级骨架），审核台提供 CSP 沙箱预览、批量采纳 / 拒绝、来源筛选、许可徽章、色板与大纲。
- **手动导入增强**：多 URL 批量（≤10 条，逐条容错，单条失败不影响其余）与 ZIP 导入（24 文件 / 24MB 上限，路径穿越全量拒绝）。
- **六资产层贯通**：组件库（素材面板拖入生成）、渐变装饰、动效模式（预算钳制 + reduced-motion 守卫，产出进 motion-lab）、风格预设（进工作台风格面板）、AI 设计分析通道（结构化 design brief + 标签）、吸收指标面板。
- **许可三档强制**：inspiration-only 档候选在采纳时**跳过代码导入**并给出原因，不只是标签展示。

### 可编辑 PPTX

- **PPTX 文件桥**：deck 产物经 python-pptx 受控映射导出标准 `.pptx`——每页标题 / 要点文本框、对比度背景、页码脚注，被扁平化的视觉元素在报告里如实上报。
- **导出中心接入 pptx**：导出报告含可编辑元素数与降级清单。
- **工作台内编辑闭环**：产物检查器「编辑幻灯片」入口 → 按页列出可编辑文本节点 → 保存后刷新 revision 徽章 / 检查器 / 实时预览。幻灯片编辑 API 带 `expected_revision` 并发保护，冲突时拒绝覆盖他人修改。

## 修复

- **装了可选依赖 `templates`（jinja2）后，deck 会变成落地页，可编辑 PPTX 完全导不出来。** 内部曾把 `deck` 意图别名到 landing 模板，只要环境中装了 jinja2，deck 请求就会被渲染成 hero / features / pricing 落地页，产物里没有一页幻灯片。结果是 PPTX 导出、幻灯片编辑 API 与导出中心的 pptx 格式全部失去输入——而失败发生在生成阶段、报错发生在导出阶段，很难定位。现在 deck 恢复意图忠实，走原生渲染器产出真正的分页结构（实测 7 页 / 24 个可编辑元素），**有无 jinja2 结果一致**。已补回归测试锁定该不变量。
- **验收脚本的 doctype 判断曾大小写敏感**，导致仅因为装 / 不装 jinja2 而翻转门禁结论（HTML doctype 按规范不区分大小写）。已改为大小写不敏感比较。

> 上述两条均为 S17 门禁在发布前发现并修复，第一条原属发布阻断级。CI 只安装 `.[dev]`（不含 `templates` extra），因此旧 CI 一路绿灯。

## 出列与后续

- **DOCX 语义导出（S15）出列至 v0.6.x。** 原计划 2 天额度让给 S17 全量回归；计划本身即允许顺延。
- **Univer 可视化画布编辑器（S13U-b2）出列，单独跟踪。** 调研结论如实说明：开源包只覆盖 slides 的模型与 UI，PPTX 导入 / 导出位于 Pro 档（`@univerjs-pro/slides*`），且 slides 没有 UMD preset，接入需要自建 vendor 构建管线。因此 v0.6.0 改为交付自研的结构化幻灯片编辑器（S13U-a API + S13U-b 对话框），它已经闭合「编辑 → 回写 → 导出」的循环；经 python-pptx 桥的**文件交付路径完全不受影响**。原「Univer 内嵌 PPTX 直接导出作为增强路径」一并移入 S13U-b2。
- **v0.6.x 首批计划**：连接级 IP 绑定（关闭 SSRF 残余风险 P1-6）、intake 编排从 `_Handler` 提为 `IntakeService`（P1-7）、P2 批次 20 项（其中 P2-10 / P2-12 / P2-13 为低风险易修项）。

## 升级说明

- **版本切换**：`pyproject.toml` / `htmlninefox/__init__.py` / `uv.lock` 已统一为 `0.6.0`。
- **deck 渲染路径变更**：deck 不再走 landing 模板兜底，改为始终走原生分页渲染。若你此前依赖"装 jinja2 时 deck 也返回 landing 页"这一行为（正常情况下不应对外依赖），需要注意产物结构变化。
- **新增可选依赖**（均非必需，缺省功能不缺失）：
  - `pptx` → `python-pptx`，启用 PPTX 导出；未安装时导出中心的 pptx 格式不可用。
  - `templates` → `jinja2`，启用模板家族。
  - `dev` extra 现已包含 `python-pptx`，便于本地跑全套测试。
- **数据兼容**：Project schema / HTTP v1 / Revision 历史不变，数据目录默认 `~/htmlninefox-output`、便携版 `user-data/`，升级不迁移、不覆盖旧项目。回滚直接安装 `v0.5.0` 即可。

## 许可与来源治理

吸收第三方设计是本版本的头号特性，因此治理与安全姿态需要明确：

- **三档许可分级**：每个内置源与候选都带许可档位，其中 **inspiration-only 档在采纳时强制跳过代码导入**，只保留灵感层面的信息。这是代码级强制，不是界面上的一个标签。
- **来源可追溯**：每个候选记录来源 id 与 kind（gallery / components / motion / typography），审核台支持按来源筛选与批量处置。
- **SSRF 姿态**：抓取侧四层防护（API 边界校验 → 抓取内再校验 → 逐跳重定向过门 → 事后 rebinding 比对并丢弃）。
- **已披露的残余风险（P1-6）**：校验用 IP 与实际连接 IP 是两次独立解析，理论上存在被绑定前的置换窗口。缓解现状与该限制均已公开记录，连接级 IP 绑定列为 v0.6.x 首项——这一点在此明示，而非静默带过。
- **预览隔离**：审核台预览走 `sandbox=""` + `default-src 'none'` + nosniff 三重约束。

## 已知限制

- Safari / WebKit 通道已用 Playwright webkit 引擎验收（22/22），但 **macOS 实机 Safari 未验证**。
- v0.6.0 的 DOCX 语义导出未包含在本版本。
- Univer 可视化画布编辑器不在本版本；工作台内编辑为自研的结构化幻灯片编辑对话框。
- 若你使用的来源页面结构与内置提取器预期差异较大，候选可能偏少——可先手动导入 URL 或 ZIP 补齐。
- DeepSeek Harness 插件仍为独立版本线的预览版。
