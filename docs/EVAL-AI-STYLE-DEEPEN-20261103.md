# 深化设计 · AI 模型全链路结合 + 风格模板矩阵（0.9.x 主规划）

**日期**：2026-11-03
**触发**：机主指令——「各类风格模板融入 0.9.x；功能深化结合：和 AI 模型结合，
怎么推动、怎么生成、怎么演示、怎么拆分、怎么组合、怎么拼装，要做到详尽」。
本文是设计总纲：先诚实盘点现状，再逐环节给深化方案，最后切分进 0.9.x 批次。
**纪律沿用**：无密钥规则引擎兜底、LLM 输出必须过既有质量门禁、CostTracker
成本透明、数据不出本机（新增：远程 LLM 环节须诚实披露数据去向）。

---

## 一、现状盘点（2026-11-03 实测，全部有代码依据）

### 1.1 LLM 基础层（已有，零新增）
| 件 | 现状 |
|---|---|
| `llm.py` | LiteLLM Router + **PROVIDER_PRESETS**：MiniMax-M3 优先（国内快/中文强）> GPT-4o > Claude；环境变量即接入；DiskCache 缓存 + CostTracker 成本追踪 |
| 兜底 | 五专家全部 `allow_llm` 开关；无密钥走离线规则引擎，功能不缺失 |
| Project Memory | brand / audience / tone / forbidden（禁词）——生成与反馈已读 |
| agent 侧 | MCP 8 工具（capabilities/analyze/generate/intake_decompose/intake_adopt/feedback/list_projects/export） |

### 1.2 五段配方流水线（骨架已在，等深化）
`recipe_run.py`：**analyze(需求分析) → compose(组合配方) → generate(生成产物)
→ verify(质量验证) → deliver(保存交付)**——五段进度、可观测 recipe-run.json、
`--revise` 无需 LLM 确定性重渲染。**这就是「怎么推动」的骨架。**

### 1.3 风格模板家底（实测数字）
| 层 | 现有 |
|---|---|
| 设计预设 PRESETS | **11 家**：linear-light · vercel-dark · guizang-magazine · shadcn-dashboard · vibrant-poster · doc-clean · fox-pixel-garden · fox-duotone-studio · fox-editorial-ink · fox-swiss-signal · fox-soft-silver |
| 意图调性 | INTENT_TONE_PRESET 六意图各配默认调性 |
| 画廊模板 | **10 张**（deck 4 / landing 2 / poster·dashboard·doc·archdoc 各 1），manifest 带 license |
| 反拆产风格 | intake 可从候选页 `build_style_preset` 入 StylePresetStore |
| 私人模板 | 导入单个 HTML / 文件夹，本地保存 |
| 联盟灵感源 | huashu-design / impeccable / guizang-ppt / motion-design（四原型表） |
| 动效 tokens | ink-in 700ms · reveal stagger 60ms cap 360 · ambient 26s ease-in-out（0.8.7 门禁锁定） |

### 1.4 LLM 今天实际在哪（诚实口径）
**只有两处**：`brief_expert`（一句话 → 结构化 brief）与 `feedback_expert`
（口语 → token 建议出 rev）。**compose（选风格）、generate（写内容）、
intake（拆分）、画布组合、演示——全是规则引擎，LLM 未参与。** 这是 0.9.x
深化的全部空间，也是「后端丰富、前端感知不深」的下一层答案。

## 二、六环节深化设计（怎么推动 / 拆分 / 生成 / 组合 / 拼装 / 演示）

### 2.1 怎么推动 —— 配方时间线 + AI 参与度可见
**现状**：五段流水线只有进度百分比；用户不知道哪段用了 AI。
**深化**：
- **配方时间线 UI**（工作台侧栏/产物详情）：五段横向时间线，每段标注
  「LLM 增强 / 规则兜底」徽章 + 耗时 + CostTracker 成本（有密钥时）；
  点开段卡片看输入摘要与产出摘要（brief 段落结构、compose 的选择理由）
- **AI 可用性徽章**：顶栏一处全局状态（检测 MINIMAX/ANTHROPIC/OPENAI
  密钥）——「AI 增强：MiniMax-M3 已接入」或「规则引擎模式（无需密钥）」，
  永远明确，不让人猜
- agent 侧：MCP 增 `recipe_status` 工具（读 recipe-run.json 五段状态）
- 门禁：时间线 UI 结构门禁 + recipe_status 真链门禁

### 2.2 怎么拆分 —— intake 语义增强提案（可选开关）
**现状**：格式解析器出结构块（带 provenance），纯结构，LLM 不参与。
**深化**（每条建议独立开关，逐条采纳）：
- **摘要压缩**：超长段落 → 提要句（保持 provenance 指回原块区间）
- **标题层级建议**：扁平文本 → H1/H2 层级建议（规则推断字号的补充）
- **口语化改写**：书面腔 → 适合网页的短句（doc/archdoc 意图收益最大）
- **表格语义化**：压平表格 → 要点列表建议（现仅压平说明）
- **讲稿要点**：PPT notes → 每页讲稿要点卡
- 交互：提案卡片右上「AI 建议」角标 + 采纳/拒绝；adopted 契约字段向后兼容
  （建议是**附加层**，不改动既有块结构）
- 兜底：无密钥 = 纯结构拆分照旧（现状即兜底态）；门禁：adopt 契约回归 +
  建议卡带 provenance 的门禁

### 2.3 怎么生成 —— LLM 进 compose 与内容层（深化的主战场）
**现状**：brief 可选 LLM；compose（选风格）与内容填充纯规则。
**深化**（三层，全部逐槽可见）：
1. **compose 推荐 LLM 化**：输入 = brief + memory（brand/tone）+ 调性选择
   → LLM 推荐 preset/模板 **+中文理由一句话**（「深色看板配 shadcn-dashboard，
   因为你强调数据密度」）；规则引擎 `match_preset` 兜底且理由照给
2. **槽位文案润色**：headline / 要点 / CTA 逐槽给 LLM 稿（约束：memory.tone、
   forbidden 禁词、长度上限），UI 呈现**原文 vs LLM 稿逐槽 diff，逐槽采纳**——
   人始终握着每一句话的最终决定权
3. **动效人格进 brief**：四原型（Playful/Premium/Corporate/Energetic）成为
   brief 一等字段 → 映射动效参数表（ink-in 时档 / reveal stagger 档 /
   ambient 幅度档），渲染器按原型取参
- 门禁：LLM 稿必须过全部既有质量闸（禁纯黑/反模式/动效/间距/对比度），
  **门禁不因 AI 豁免**；无密钥 = 槽位原文照旧；采纳率埋点（本地统计，不出网）

### 2.4 怎么组合 —— 风格轴矩阵（机主点名的风格模板主场）
**现状**：11 preset × 10 画廊 × 6 意图自由组合，但无调性语义、有矩阵空洞
（dashboard 只有 1 张模板）。
**深化**：
- **调性四原型**成为全局选择器（生成面板 + 画廊筛选共用）：
  Playful 弹跳 / Premium 从容 / Corporate 干练 / Energetic 锐利
- **覆盖矩阵门禁**：6 意图 × 4 调性 ≥ 1 个可产出组合（preset×模板映射表
  驱动；空洞处补模板或映射）——矩阵完整是发版门禁
- **画廊 B 档**：10 → 18 张（补 dashboard/poster/doc 空洞），每张 manifest
  增 `tone` 标签；**C 档**：外部库 34 套接入（license 字段随附）
- **风格说明书**：选定「意图×调性×preset」后，LLM 生成一段中文风格说明
  （这段页面想传达什么、动效什么性格），存入 memory 可复用；规则引擎版 =
  从 tone 参数表拼装固定话术
- 门禁：矩阵门禁 + tone 标签完整性门禁（manifest 全体必须带 tone）

### 2.5 怎么拼装 —— 块→槽位拼装层（0.9.x 最重的新能力）
**现状**：拆分产物只能「整篇采纳」成新产物；拆出来的块没有第二生命。
**深化**（分两步走）：
- **第一批（0.9.y）：块拼装**——审核台提案里的块可多选 → 「拼装成新产物」
  → 选目标意图/调性 → 块自动映射到模板槽位（规则映射：标题→headline、
  要点→bullets、表格→stats）→ LLM 建议（哪个块进哪个槽 + 缺槽内容补写
  建议）→ 进既有生成管线。**拆分与生成在这里首次打通：拆开的块有第二生命**
- **第二批（v1.0 前奏）：站点结构**——多产物 → 工作区拼装建议（导航层级/
  索引页），先出「结构 JSON + 索引页导出」，为 v1.0 多页站铺路（不碰单文件
  承诺，结构作为附加产物）
- 门禁：映射规则表测试 + LLM 建议必过槽位 schema + 无密钥纯规则映射照旧

### 2.6 怎么演示 —— 演示模式 + AI 讲解词
**现状**：预览 / 手机预览 / 五格式导出；deck 动效是活的但只能手动看。
**深化**：
- **deck 全屏演示**：全屏 + 键盘翻页（←→/空格）+ 每页入场动效重触发 +
  ESC 退出；手机扫码直达演示模式（手机预览 URL 加 `?present=1`）
- **首屏巡礼**（landing/dashboard）：滚动驱动自动播放，逐卡显形按 stagger
  预算走（复用 0.8.7 动效层）
- **AI 讲解词**：按产物结构生成逐段讲稿（每页/每卡一两句），演示模式底部
  可开可关；规则引擎版 = 直接读结构标题串讲；讲稿属附加文本，不入产物本体
- 门禁：演示模式结构门禁（存在性 + 翻页键）+ 讲稿不污染产物内容的门禁
  （讲稿只存在于演示会话/导出旁车文件）

## 三、风格模板矩阵总表（0.9.x 交付后的形态）

| 维度 | 0.9.x 后 |
|---|---|
| 调性 | 4 原型（Playful/Premium/Corporate/Energetic），全局选择器 |
| 设计预设 | 11 家（0.9.x 内 ∓2：按矩阵空洞补 fox-* 新族） |
| 画廊 | 10 → **18**（B 档）→ +外部库 **34** 套（C 档，license 随附） |
| tone 标签 | 全体模板/预设 manifest 必带（完整性门禁） |
| 动效 | 四原型 → 动效参数表（ink/reveal/ambient 三轴），0.8.7 门禁护栏内 |
| 反拆产风格 | StylePreset 打上 tone 推断标签，进同一矩阵 |

**矩阵门禁**：6 意图 × 4 调性 ≥ 1 可产出组合——发版前机器验证，空洞不可发版。

## 四、AI 纪律（全环节统一，写进门禁）

1. **无密钥不缺失**：每个深化点都有规则引擎兜底态，兜底态全量测试照跑
2. **质量闸不豁免**：LLM 参与的产物照过全部既有门禁
3. **成本透明**：CostTracker 数字进配方时间线（有密钥时）
4. **数据去向诚实**：首次使用远程 LLM 环节时，一次性提示「此环节内容将
   发往你配置的供应商」；本地模型（Ollama 类）接入不触发提示
5. **人握最终稿**：槽位采纳制——LLM 稿永远只是建议，逐槽决定

| 批次 | 内容 | 依赖 | 规模 |

| **0.9.3** | **拆分语义增强**（2.2 四类建议卡）+ **演示模式**（deck 全屏 + 首屏巡礼 + AI 讲解词） | 0.9.2 的 LLM 会话层 | ≈3 天 |

| **0.9.5** | **模板 B/C 档**：画廊 18 张 + 外部库 34 套 + 市场 UI（分类/搜索/调性筛选） | 0.9.1 tone 标签 | ≈4 天 |

**首推 0.9.1**：把已有家底（11 preset × 动效 tokens × gallery × 四原型表）
串成可感知的调性体验，同时给 0.9.2 的 AI 深化铺好「调性」这个关键输入——
小步、自足、可发版。
