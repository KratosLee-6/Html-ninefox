**日期**：2026-10-31
**触发**：机主观察「后端很丰富，前端使用感知不深」——正是 PLAN 队列里挂着的
「下一北极星讨论：输入缺口清零后主战场转向输出端」。本档是讨论的开局：
先诚实审计缺口，再给候选排序，**由机主勾选后才立项**。

## 一、缺口审计：后端能力 vs 前端可感知

| 后端已有 | 前端现状 | 感知缺口 |
|---|---|---|
| 生成产物落盘（847 测试护住） | 预览 iframe（死预览，动效活但不可点改） | **不能点哪里改哪里** |
| 反馈改写（token 级，rev 历史） | 口语一句话（整页重渲染） | 改稿粒度粗，无局部微调 |
| 幻灯片文本原位编辑（deck 专用） | 只有 deck 有 | 其他五类意图无同款 |
| 五格式导出 | 导出中心逐个导 | 无「一键交付包」 |
| 局域网访问（--host 0.0.0.0） | 文档警告无鉴权 | 无手机预览引导（二维码） |
| Project Memory（品牌/受众/语气学习） | memory-modal 有底子 | 「越用越懂你」不可见 |
| 画廊 10 张模板 | 侧栏「版式」平铺 | 无分类/搜索/市场感 |
| 单文件 HTML 交付形态 | 有意承诺 | **多页站点**从立项起空白 |

**结论**：缺口不是能力缺失，是**能力的最后一公里没有界面化**。后端每一步
都有 API 与门禁，但用户坐在工作台里，最直观的三个动作——「点着改」「发到
手机看」「一键打包交付」——要么缺失要么藏得深。

---

## 二、候选提案（按感知价值排序）

### A · 所见即所得编辑（Live 预览编辑）★ 推荐主打

预览 iframe 里**点击任意元素 → 浮动工具条 → 直接改文字/换色/调间距**，
写回 output.html 并存 revision。与口语反馈共用版本机制（可对比可回滚）。

- 架构基础（全部已在）：产物是我们自己生成的（token 结构已知）；同源 iframe；
  幻灯片编辑器已验证「原位编辑」模式；`apply_text_edits` 机制已存在（v0.6
  为 deck 文本而建，可推广）
- 分期：A1 文本级点选即改（复用幻灯片编辑模式，**约 2 天**）→ A2 样式级
  点选即改（token 映射，**约 3 天**）
- 感知：最高——「我点哪里改哪里」是设计工具的体感分水岭
- 门禁：edit 与 preview 一致性（v0.7.4 教训直接适用）

### B · 手机预览 + 二维码（小而美）

工作台一键「发到手机看」：检测局域网地址 → 渲染二维码 → 手机扫码即看产物
（390px 已实测适配）。加安全提示（无鉴权，仅限可信局域网）。

- 成本：**约 1 天**（含 qrcode 可选依赖或纯 JS 生成）
- 感知：高——「做完马上掏手机看」是最自然的验收动作

### C · 一键交付包（导出中心收口）

导出中心加「交付包」：HTML + PDF + PPTX/DOCX 按意图自动组包打 zip + 清单。
- 成本：**约 0.5 天**（导出管线全在，只是编排）
- 感知：中高——「交付出厂一键完成」

### D · 模板生态 UI（模板 B/C 档的界面呈现）

画廊 10 → 18 张（B 档已排）+ 外部库 34 套接入（C 档）：分类/搜索/预览/
一键采用的**市场感 UI**，替代侧栏平铺。

- 成本：B 档本身 3 天 + 市场 UI 1 天
- 感知：中高——「选择像逛商店，不像猜谜」（v0.8.1 的老话）

### E · 多页站点（Site 模式）★ v1.0 级

一个项目产出多页网站（index + 子页 + 导航），打包 zip 交付。

- 打破的是「单文件」这个**有意承诺**——需要立项重审：多页作为**新增产物
  形态**与单文件并存（不替换），导出/预览/版本全链路多页化
- 成本：**1–2 周**（渲染器/导航/导出/门禁全链路）
- 感知：最高（真实网站），但风险与体量也是最高——建议 v1.0 主打，0.9 不碰

### F · 品牌套件可视化

memory-modal 升级：把 Project Memory 学到的品牌资产（受众/语气/主色/字体/
模板偏好）可视化成「品牌套件」面板，一键应用/清除。

- 成本：**约 1 天**（数据与学习机制全在，纯界面）
- 感知：中——「它越用越懂我」从感觉变成看得见

## 三、组合建议

| 包 | 内容 | 总成本 | 适合 |
|---|---|---|---|
| **快赢包** | B + C + F | **≈2.5 天** | 三个小感知点一次交付，发 0.8.6 |
| **体验大版** | A（A1+A2）+ B | **≈6 天** | 「点哪里改哪里」+ 手机看，发 0.9.0 前哨 |
| **v1.0 预研** | E 多页站点 | 1–2 周 | 输出端正主，建议单独立项 |

**推荐**：先做**快赢包**（B+C+F，小步快跑），同时把 **A 所见即所得** 立为
0.9.0 的第二主项（与 Tauri 壳并行不冲突——壳是桌面形态，A 是编辑体验），
**E 多页站** 立为 v1.0 讨论（不在 0.9 动）。
